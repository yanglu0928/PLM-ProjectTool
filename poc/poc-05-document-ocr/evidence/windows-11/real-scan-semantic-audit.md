# Windows 11 真实扫描件语义准确率审计

## 结论

`PASS`

5 份匿名扫描 PDF 共 105 页。本轮在每份文档固定抽取前部正文、中部正文和后部正文各 1 页，共 15 页；从原页渲染图先行视觉抄录 75 个检查点，再与 OCR 输出比较，避免由 OCR 自身生成真值。

PaddleOCR 主链命中 75/75，语义检查点召回 100%，17 个关键检查点和 12 个数值/代码精确检查点均为 0 错误，满足“召回不低于 95%、关键错误为 0”的 PoC 门槛。

现有 Tesseract 辅助链命中 70/75，召回 93.33%，含 2 个关键错误和 1 个精确字段错误，结果为 `FAIL`。因此 Tesseract 保留为辅助回退，不得作为关键金额、日期、版本、电话号码或代码字段的唯一来源；这些字段若只由辅助链提供，必须进入人工确认。

## 方法边界

- 页面使用 Poppler 以 300 DPI 在本机渲染，PaddleOCR 使用已缓存的 PP-OCRv5 mobile 检测与识别模型，未联网。
- 语义文本允许归一化后的相似度不低于 0.85；数值、代码和版本字段要求归一化后完全一致。
- 抽样覆盖正文、接口、验收、权责、金额/期限及复杂表格，不把空白页或仅封面页计入样本。
- 本结果是分层抽样准确率证据，不等同于 105 页逐字符全量标注，也不形成生产容量或所有扫描质量的保证。
- 原文件名、正文、渲染页、人工检查点、逐项分数和客户信息仅保存在 Git 忽略的本地 `artifacts`，仓库只保留匿名汇总。
