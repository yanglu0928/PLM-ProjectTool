# Windows 11 真实方案库解析证据

## 范围

2026-09-17 在 Windows 11 上，以仓库根目录下被 Git 忽略的 `方案库/` 作为只读输入，执行 POC-05 统一解析器批量验证。原文件、原文件名、Hash、解析正文及本地映射均未提交到 Git。

## 结果

- 输入总数：18 个，365,328,831 字节。
- 格式：DOCX 11、PPTX 5、PDF 1、旧版 DOC 1。
- 当前支持格式：17 个；统一解析和 JSON Schema 校验 17/17 PASS。
- OOXML 包完整性：16/16 PASS。
- 输出统计：492 个页/幻灯片或显式页对象、13,710 个块、2,399 个表格行。
- 原件不变性：18/18 PASS。
- 批次总耗时：22.110 秒。
- 旧版 `.doc`：1 个，`UNSUPPORTED`。
- 批次结论：`PARTIAL_PASS`。

唯一 PDF 共 81 页，80 页存在稳定文本层，1 页文本少；本批按文本 PDF 解析，不执行整本 OCR。方案库没有真实扫描 PDF，因此本批不能关闭真实扫描件 OCR 质量缺口。

## 隐私边界

仓库证据 `solution-library-validation.json` 只包含脱敏文档编号、扩展名、大小、计数、状态和耗时，不包含：

- 原文件名或目录结构；
- 文件 Hash；
- 标题、正文、表格内容；
- 客户名称或项目名称；
- 原始运行日志。

逐文件映射和 ParsedDocument JSON 仅保存在 Git 忽略的 `artifacts/poc-05/solution-library/2026-09-17-r3/`。

## 已修复问题

1. PDF 自动分类最初因 81 页中有 1 个低文本页而对整本启动 OCR。规则已调整：低文本页占比不超过 10% 时按文本 PDF 解析并保留统计，避免无意义的全本 OCR。
2. 1 个 DOCX 含有名称为空的段落样式对象，触发空值错误。解析器已把该情况按空样式处理并增加单元回归测试；全量复跑后 17/17 个支持文件通过。

## 限制

- 这次运行没有人工标注答案集，只能证明结构化解析、Schema 和来源定位可执行；不能量化语义完整率。
- 旧版二进制 `.doc` 不属于当前 POC-05 锁定格式，未自动转换。
- DOCX 页数仍只反映显式分页，不代表 Microsoft Word 的自动排版页数。
