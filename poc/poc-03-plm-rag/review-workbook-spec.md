# POC-03 Golden Dataset 人工评审工作簿规范

## 用途

将 P0.09 产生的 120 条 `PENDING_HUMAN_REVIEW` 候选记录交给人工逐条确认。工作簿是本地评审工具，不是正式 Golden Dataset，也不改变候选记录的审核状态。

## 工作表

|工作表|用途|
|---|---|
|评审总览|显示候选数、审核状态、可转正式集数量、来源分布和评审步骤。|
|候选评审|保存 120 条候选明细、人工输入、审核状态和公式计算的完备性。|

## 字段与控制

- 灰色列：候选编号、范围、ProjectId、脱敏文档编号、Chunk 编号、建议引用定位、候选正文和正文 Hash，只作为来源证据。
- 黄色列：人工查询、来源类型、预期分类、答案关键术语、确认引用定位、审核状态、审核人、审核时间和审核备注。
- 绿色列：公式计算的完备性，不允许用人工文本替代。
- 来源类型下拉值：`STANDARD_CAPABILITY`、`CONTRACT`、`TECHNICAL_AGREEMENT`、`SURVEY`。
- 预期分类下拉值：`STANDARD_SATISFIED`、`PARTIALLY_SATISFIED`、`NON_STANDARD`、`INSUFFICIENT_INFORMATION`、`NO_RELIABLE_MATCH`、`HUMAN_CONFIRMATION_REQUIRED`。
- 审核状态下拉值：`PENDING`、`APPROVED`、`RETURNED`。

## 可转正式集规则

只有同时满足以下条件，完备性才显示“可转正式集”：

1. 审核状态为 `APPROVED`。
2. 人工查询不为空。
3. 来源类型不为空。
4. 预期分类不为空。
5. 答案关键术语不为空。
6. 确认引用定位不为空。
7. 审核人不为空。
8. 审核时间不为空。

其余记录保持“待评审”或显示具体缺失字段，不得计入正式 Golden Dataset 和质量指标。

## 隐私边界

- 工作簿含本地客户资料片段，只保存在 Git 忽略的 `artifacts/poc-03/review-workbook/`。
- 不上传 DeepSeek 或其他外部服务，不提交 Git，不记录原始文件名。
- 仓库只保存工作簿结构、数量、控制规则和脱敏验证结果。

## 当前验证结果

- 120 条候选全部导入；来源分布为历史方案 75 条、技术协议/合同 45 条。
- 初始状态为 120 条 `PENDING`、0 条 `APPROVED`、0 条可转正式集。
- 3 组下拉规则、冻结表头与前两列、筛选表和条件格式已写入 XLSX。
- 已验证“缺少审核时间”和“字段齐全”两个边界，完备性分别保持阻塞和变为“可转正式集”。
- 内存工作簿和导出后回读工作簿的公式错误扫描均为 0。
