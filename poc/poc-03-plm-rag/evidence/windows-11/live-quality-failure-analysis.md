# P03-A11~A13 Windows 11 首轮失败分析

## 结论

首轮 120 条真实 Golden Dataset 验证完整执行，但三项质量门槛均未达到，因此 P03-A11、P03-A12、P03-A13 均判定为 `FAIL`。不得以合成数据结果、同文档命中或模型输出格式恢复替代正式门槛。

|指标|结果|门槛|判定|
|---|---:|---:|---|
|Top-5 Recall|72/120，60.00%|≥95%|FAIL|
|分类准确率|17/120，14.17%|≥90%|FAIL|
|来源引用准确率|61/120，50.83%|≥98%|FAIL|

基础执行链完整：1,815 个真实向量来自 `qwen3.7-text-embedding`，120/120 次重排使用 `qwen3-rerank`，PostgreSQL 18.6 的 GIN 与 pgvector HNSW 均实际命中，120 条预测全部返回，越界引用为 0。

## 脱敏诊断

1. 精确 Chunk 召回 72 条，而同文档召回 88 条。16 条属于已找到正确文档但落在相邻或不同 Chunk，另有 32 条未在 Top-5 找到期望文档。合同为 16/20 精确命中，标准能力为 44/76，调研为 1/4，技术协议为 11/20。
2. 61 条引用命中均位于合法 Top-5 内，且没有模型自造或越界 Chunk；但引用准确率受 60% 的精确召回上限约束，并且在 72 条已召回样本中仍有 11 条未选中期望 Chunk。
3. 分类失败不能仅归因于检索：精确召回的 72 条中分类只正确 10 条（13.89%），未召回的 48 条中正确 7 条（14.58%）。
4. 期望分类中 `HUMAN_CONFIRMATION_REQUIRED` 为 52 条，模型只输出 1 条；模型输出 `STANDARD_SATISFIED` 75 条，而期望仅 13 条。当前 R4 导入规则对多数“修改后确认”仍保留候选阶段的关键词启发式分类，只对两组明确短语做确定性重映射。该分布不能证明人工标签错误，但说明当前确认界面没有逐条采集明确的最终分类，标签一致性尚未得到可审计验证。

## 保持不变的边界

- 未降低 95% / 90% / 98% 门槛。
- 未根据模型输出事后修改 Golden Dataset 标签或期望 Chunk。
- 未更换 DeepSeek、Embedding、Reranker，也未改变已登记的 Hybrid 0.6/0.4 基线。
- 查询、正文、向量、逐条模型响应和客户文件继续只保存在 Git 忽略的本地目录。

## 建议的修复顺序

1. 先重新打开 Golden Dataset 标签 Gate：在友好确认界面中把“最终分类”设为明确必填项，展示 AI 建议、人工最终值、理由和证据位置，不再从自由文本或早期关键词建议隐式继承正式标签。
2. 标签冻结后再做检索诊断：分别记录 Vector Top-20、FTS Top-20、融合候选和 Reranker 前后排名，分析 32 条文档级漏召回与 16 条相邻 Chunk 偏移；只有来源类型属于真实查询上下文时，才评估来源类型过滤。
3. 在冻结的分类定义上补充版本化判定示例并重跑统一 AIService；不得把期望标签或期望 Chunk 放入 Prompt。
4. 任一检索参数、标签基线或验收定义变化均生成新版本并保留本轮 R1 失败证据。

## Gate

需要用户确认是否按上述顺序重新打开 Golden Dataset 标签评审并开展检索调优；在确认前，POC-03 保持 `FAIL / BLOCKED_QUALITY_GATE`，不进入下一 WBS。
