# POC-03 独立留出集真实质量复验失败分析

## 结论

2026-09-21 在 Windows 11、PostgreSQL 18.6、pgvector 0.8.6 上完成 50 条独立留出集真实复验。Top-5 Recall 为 49/50（98.00%），达到 95% 门槛；分类准确率为 24/50（48.00%），低于 90%；精确来源引用准确率为 37/50（74.00%），低于 98%。POC-03 总体保持 `FAIL / BLOCKED_QUALITY_GATE`。

## 链路完整性

- 2,056 个唯一 Chunk 与 50 个查询完成 2,106 个真实 Embedding 向量缓存。
- 50/50 条百炼 `qwen3-rerank` 真实重排完成。
- 50/50 条 DeepSeek `deepseek-flash` Prompt v2 预测完成。
- PostgreSQL GIN 与 pgvector HNSW 均实际命中。
- 缺失预测 0，越界引用 0，ProjectId 和来源类型隔离保持启用。
- 首次数据库装载发现 17 个重复 ChunkId、22 行冗余记录。核验确认全部逐字段相同；修复只合并完全一致记录，同 ID 不同内容继续失败关闭。

## 主要失败模式

分类失例 26 条。模型将 44/50 条预测为 `STANDARD_SATISFIED`，而人工真值中该类只有 23 条；13 条 `INSUFFICIENT_INFORMATION` 只有 1 条分类正确，10 条 `NON_STANDARD` 没有分类正确，说明 Prompt v2 仍倾向把“检索到相关文字”直接解释为“标准能力满足”。

引用失例 13 条。检索命中 49/50，引用命中只有 37/50，表明剩余问题主要发生在已召回候选中的精确证据选择，而不是候选缺失。按来源看，`STANDARD_CAPABILITY` 为 24/33，`CONTRACT` 为 6/7，`TECHNICAL_AGREEMENT` 为 7/8，`SURVEY` 为 0/2。

## 处理决定

1. 冻结本轮 98.00% / 48.00% / 74.00% 结果，不修改门槛、人工标签或引用真值。
2. 本轮 50 条已成为已见测试集，不再用于“独立未见集通过”声明。
3. 下一轮先在独立开发/校准集上处理分类语义和精确引用选择，不在本留出集上逐条编码规则。
4. 修复后必须建立全新的独立留出集，再判断 P03-A12/P03-A13 是否通过。
