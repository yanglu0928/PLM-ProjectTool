# CR-PRJ-002：成员创建幂等结果快照

日期：2026-09-25；状态：依据 CR-EXEC-001 持续授权批准执行；范围：PRJ-04-A10 幂等前置。

## 差异与证据

冻结 API-01 要求同一 Idempotency-Key、同一请求重放首次成功的语义响应。现有通用 `plt_idempotency_receipts` 只保存结果引用，CR-API-001 明确禁止把可变资源当前视图冒充历史响应。`ProjectMemberView` 中角色、部门、状态、ETag 和用户/部门显示名称均可能在创建后变化；仅引用 `prj_project_members` 不能满足合同。

## 方案与影响

拒绝从当前成员行重建历史结果（会漂移），也不把响应正文或客户内容塞入通用收据（违反最小化和模块归属）。选择新增 Project-owned、仅追加的 `prj_member_create_results`：以成员 ID 为主键，保存首次 201 MemberView 的类型化字段及项目归属；收据仍只保存引用。成员创建、快照、审计和收据完成在同一事务提交。重放须重新验证当前 Session/CSRF、License 和 ProjectManager 身份；结果从不可变快照读取，不重复成员创建与审计。不同载荷同 Key 保持 409。

此为冻结 DB Schema V1 后的可追溯增量，不回写 Gate 2 原冻结提交。`/api/v1` 路径和响应结构不变；不增加跨模块数据访问。既有成员不补造快照，只有经新幂等入口创建的成员拥有快照。

## 迁移、验证与回退

Migration `20260925_0016` 在空库和已有数据上只建新表，不改原记录；ORM 与迁移同步。验证包含单元、PostgreSQL 空库/已有数据升级、同 Key/异载荷/并发/失败回滚、创建后成员或显示名称变更仍原样重放、迁移 up/down。降级仅当快照表为空时允许，以免丢失幂等证据；已有快照时须保留版本或先执行受控迁移，不直接删除。升级前备份数据库。生产信任源、Server 2025 与 Debian 13 不由本项宣称已验证。
