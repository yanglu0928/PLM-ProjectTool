# CR-SOL-019：OutlineVersion 历史读取生产游标密钥升级前置

日期：2026-10-09。状态：P04 组合时识别运行兼容性差异并补记；依据 `CR-EXEC-001` 持续授权实施，不追写 Gate2 冻结提交 `64cdf09`。TraceLink：Gate2 API-04 → A05-A03-P01～P03 → 本 CR → P04 Windows 组合 → Release 密钥供给/恢复。

## 差异与证据

原生产只读/读写平台不需要 `project-outline-version-list-cursor-v1`。新增 OutlineVersion 历史 GET/LIST 需要独立 HMAC-SHA256 游标密钥；Windows 生产组合若无此密钥即失败关闭，因而直接升级旧部署会改变启动前置。登录专用模式不注入历史读路由。本差异是部署密钥要求，不改 Gate2 路径、角色、Schema 或历史数据。该升级前置在 P04 实施过程中识别，本记录不伪称早于代码实施。

## 方案、风险与迁移/回滚

采用当前服务账户 Windows Credential Manager 的独立 32 字节密钥引用，不复用 Outline/Section/Reference 或其他 key；提供单独加密备份并受控恢复，生产代码只读、不自动生成或覆盖。部署顺序为先以目标服务账户安全供给并验证密钥及恢复，再升级/启用只读或读写平台。缺密钥/错误长度时不暴露具体异常，拒绝启动并释放数据库资源。风险包括漏供给导致可用性中断、轮换丢失导致旧游标不可解，以及服务账户 ACL 不正确。回滚可关闭/移除新增历史路由组合并恢复旧程序，保留历史版本；不得删除既有数据或用其他用途的 key 顶替。

## 验证与剩余边界

合成随机临时引用在 Windows 11 当前账户验证失密、加密备份恢复旧游标，生产合同验证两平台模式缺 key 拒启动/资源释放；隔离 PG18.6 工厂双 Scope ASGI 验证通过。未供给正式服务账户、未验证目标 ACL/备份保管、Windows Server 2025、正式包安装/恢复；这些仍为 Release 阻塞，不因本 CR 记录而关闭 Gate3。Debian13 实机依用户指令跳过。
