# CR-AI-005：AIModel 状态命令不可变首次结果

日期：2026-10-02；状态：按 V1.1 持续授权登记，P01 Schema 已在隔离 PG18 验证；P02～P04 待实施。关联 CR-AI-004；Gate 2 原冻结提交 `64cdf09` 保留。WBS：`AI-02-A08-P01`。

原方案/差异证据：冻结 API-03 的 `AI_MODEL_SET_STATE` 返回 200 状态，通用幂等收据只保存对象 ID/状态码。Schema 0057 的 `ai_models` 保存当前状态/版本，可能在首次成功后再次转移；仅凭收据或当前行无法可靠重建第一次 200 的状态和 ETag。现有 Provider 激活和 Project 成员状态已经使用独立不可变首次结果记录。

方案比较：A 重放时读取当前模型行，首次响应会随状态变化，否决。B 在通用收据塞入动态 JSON，扩大跨模块平台存储边界，否决。C 新增 AI 自有不可变 `ai_model_state_results`，绑定模型/操作者/Audit/操作/转移前后状态及版本，选择 C。

影响/风险：在 0057 后增加 0058 普通增量表与 ORM，不改冻结状态枚举、语义身份、API 路径或依赖。Schema 仍允许历史引用，但业务仅开放 SUSPEND/RETIRE；AVAILABLE/质量证明不在本变更授权内。新增表若缺约束可能产生伪造结果，因此需行级/截断历史保护、版本关系与 Audit FK，并在命令实现时由同事务落库。

迁移/回滚：0057→0058 空库及有模型历史升级；空结果表可 down 回0057，若有状态结果则拒绝物理降级并保留历史向前修复。不得清除已有模型或审计。正式生产迁移另需备份及目标账户验收，本次只用隔离 PG18。
