# CR-AI-007：PromptVersion 内容准入信任源

日期：2026-10-02；状态：依 V1.1 持续授权登记，P03-A01 合成验签/隔离 PG18 已通过；正式审查/密钥/发行仍待；关联 DEC-677、CR-AI-006；原 Gate 2 冻结提交 `64cdf09` 保留。WBS `AI-03-A04-P03`。

冲突与证据：冻结 DM/API-03 禁止 PromptVersion 含真实 API Key、固定客户资料、Golden 答案或绕过 Evidence/Review 指令。P02 的规范化/明显密钥形态检查不能判定任意语义；合成准入端口也不具备生产信任。直接开放管理员自由文本入口将把未经审查内容永久写入不可变历史。

方案比较：A 仅用正则/AI 自评，无法覆盖未知秘密和语义绕过，否决。B 只允许编入代码的固定 Prompt，限制冻结版本管理的实际用途，否决。C 开发者工作台离线审查并签名一个精确指纹清单，运行时用独立 Ed25519 公钥、已钉住的清单摘要和格式/作用域校验准入任意已审查版本；选 C。签名只能证明授权来源和内容未变，不能替代真实审查记录或 AI 质量验收。

与原方案差异：新增独立 Prompt 准入签名信任锚及清单分发流程；不复用 License 私钥，不改冻结 `/api/v1`、PromptVersion 字段、AIService 边界或技术栈（`cryptography` 已是正式依赖）。清单只保存模板 UUID、TaskType、正文/策略联合指纹、审查元数据，不含正文、Key、客户数据或 Golden 答案。

风险与控制：伪造签名、清单回滚、跨模板重放、重复键、畸形 JSON/超大输入和公钥失配全部失败关闭。运行时须用受信发行配置钉住签名清单 SHA-256；不能从请求里提供公钥或期望摘要。签名人/审查日期字段只是追溯线索，真实性仍依赖工作台仪式、密钥保管、源码/清单评审和发行验收。正式私钥仅在开发者工作台，需离线备份；不得进入 Git/客户包/服务器。

实施顺序：P03-A01 实现只读验签与精确指纹准入，使用临时合成密钥测试；P03-A02 受控工作台清单生成/签名、正式公钥与审查流程/目标账户装配；之后才允许公开增版 HTTP。无正式信任锚时生产保持关闭。

迁移/回滚：无数据库迁移。P03-A01 不装配可撤回；已持久 PromptVersion 不物理删除。若正式清单撤销或更新，发行配置钉住新摘要并验证升级/恢复，旧清单不得复用。正式清单生成和密钥仪式尚未执行。

验证计划：签名正常/篡改、错误公钥、错误钉住摘要、重复 JSON key、未知字段、空/重复/乱序条目、跨模板/TaskType、过大清单、错误编码/签名长度；合成 PG18 正式增版服务绑定验证；后端回归与开发包构建。真实模板审查、正式公钥/私钥保管、离线安装/升级和 Gate 3 另行验收，不能由合成 PASS 代替。

P03-A01 结果：进程内临时 Ed25519 密钥、只含合成指纹的清单验证通过；错误摘要/公钥/篡改及结构负例失败关闭，Win11 隔离 PG18 内部增版仅允许精确列入指纹。正式审查人、密钥仪式、发行钉住来源和生产路由均未提供。

P03-A02-P01 结果：工作台工具从完整候选计算指纹、交互式摘要确认后用独立加密私钥签名，只创建仓库外无正文清单；临时密钥合成签署/运行时验签通过。编码中发现原 `PromptVersionDraft` 三个引用字段虽受格式约束，却未拒绝形如密钥的值。签署工具负例暴露遗漏；若不修复，密钥样式可进入不可变元数据。选择在原 Domain 输入规则增加同一明显密钥形态拒绝，不改已有合法值/API/Schema；无数据迁移，代码回滚可恢复旧拒绝范围但不应降低生产安全。定向6、后端2070项通过/3项既有跳过、开发wheel通过；正则仍不能证明任意秘密不存在，人工审查保持必需。正式密钥/审查/发行仍未验。
