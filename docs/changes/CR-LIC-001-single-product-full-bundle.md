# CR-LIC-001：首版 License 单产品、全功能整体授权

|字段|内容|
|---|---|
|级别|L3：已锁定安全/License 规则变更|
|日期|2026-09-24|
|状态|APPROVED_BY_USER|
|用户明确批准|“明确同意修改已锁定方案，采用方案B”|
|起因|`docs/progress/lic-02-a02-payload-conflict.md`：七字段签名 Payload 不含产品或功能权益，无法履行原 ADR-006/DM-02 的细分验证要求。|
|变更边界|保留 `plm.license.v1` 七字段 Payload、确定性 UTF-8 JSON、MAC 规范化→SHA-256→Ed25519、开发者工作台私钥隔离、有效期与可信时间。首版只有 PLM 项目实施辅助工具这一产品，授权按完整功能集整体生效/失效；不发行也不解析按产品或功能差异化的权益。|
|产品身份|由发行方限定的本产品可信 Ed25519 公钥引用/发布配置确定，不从七字段 Payload 推断产品。若公钥可跨产品复用，则不得视为可安全识别本产品；生产装配必须限定发行公钥只签发本产品 License。|
|状态投影|`entitlement_snapshot` 仅记录由已验证签名、固定发行配置和有效期派生的最小状态；不得把没有签名来源的产品/功能列表写成已验证权益。|
|兼容性|现有 v1 签名文档字段及序列化不变；现有 PoC 仅证明密码学/机器/时间技术可行，不自动成为生产有效 License。未来若需要多产品或按功能授权，另提 L3、版本化签名 Payload 与迁移策略。|
|不变项|不改 `/api/v1` 路径、License 安装/验证/可信时间表、目标 OS、技术栈和其他模块 Scope。|
|风险|不能通过单个 License 控制细分模块；公钥跨产品复用会削弱产品身份隔离；生产公钥注册、Secret Store 和初始化仍待实现。|
|验证|本变更首先以文档一致性检查验收；LicenseService 行为与真实签名/机器/时间负例由后续 LIC-02-A02 验证。|

本 CR 是《PLM项目实施辅助工具软件开发实施方案 V2.1》的 License 专项正式补充，优先于该方案与 Gate 2 冻结候选中冲突的产品/功能细分表述；其余冻结内容和提交 `64cdf09` 的历史保持不变。
