# CR-AUT-009 会话响应时间统一 UTC

2026-09-28 / Phase2 AUT-05-A06 / 状态：IMPLEMENTED_AND_VERIFIED（仅本项合同修复；Gate3 未通过）。

## 原基线与差异

Gate2 冻结的 `API-CONTRACT-CANDIDATE-V1`（原提交 `64cdf09`）规定响应时间为 RFC3339 UTC、以 `Z` 结尾。现有登录、会话 GET、续期 Router 直接调用 `datetime.isoformat()`；AUT05A05 实际浏览器/PG18.6证明数据库读出的会话过期时间可能是 `+08:00`，客户端原严格UTC校验因而拒绝有效的GET/续期响应。前端已在A05做严格offset兼容并归一化；此兼容不解除服务端的冻结合同义务。原冻结文档和提交不追写。

## 选择、影响和回滚

- 方案A：只保留前端兼容、服务端继续返回偏移时间。不选；冻结合同仍不满足。
- 方案B：只在Auth HTTP投影统一将有时区时间转换为UTC并输出`Z`；登录、GET、续期三路径共享严格格式函数，对naive/无效时间失败关闭。不改实例时刻、Cookie Max-Age算法、Session存储、字段、错误码、权限或冻结API结构。选择B，按用户2026-09-24持续授权实施。
- 风险：历史客户端若错误地把`+08:00`字符串当作不含时区的墙上时间，显示可能不同；对合规RFC3339客户端，该改动仅保持同一时刻、提高合同一致性。旧正确`Z`响应不变；本项无DB迁移、依赖或离线数据变换。回滚可还原Router格式化，客户端A05偏移兼容仍保留，但回滚后合同违例重现，不可据此关Gate。
