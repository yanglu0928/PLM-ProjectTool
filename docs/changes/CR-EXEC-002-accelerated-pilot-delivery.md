# CR-EXEC-002：Windows 11 内部试用包优先的加速交付顺序

日期：2026-10-10；来源：用户同意“先交付 Windows 11 内部试用包，再完成正式多平台发行”，并要求更新 `AGENTS.md`、尽快自动完成开发。状态：APPROVED_BY_USER / 执行中。继承 CR-EXEC-001 的持续自主执行和安全边界。

## 差异与方案

原 V2.1 以 Phase 2～12 和 Gate 3～7 作为正式交付顺序；当前多个模块的单点 Owner/HTTP/Edge 已通过，但方案→WBS→输出的完整纵向链、AI 质量、20 并发性能、正式 License/服务账户信任源及离线安装仍未达标。若只按各模块横向补全再开始打包，首个可运行包将推迟，集成问题也会集中在末期暴露。

选择**增加中途验收物**，不删首版 Scope 或正式兼容目标：先在 Windows 11 制作受控内部试用包（Pilot），把项目→交接→调研→需求→原型→方案→WBS→输出的最短真实纵向路径、真实安全装配和离线安装作为优先关键路径；其余正式功能、三平台安装升级、性能、AI 质量、插件及 UAT 继续按原 Gate 单独收口。Pilot 只作内部试用，不标 Gate 3～7 PASS，不称正式 Release，不以合成 License/客户确认/来源数据冒充生产事实。不能满足 Pilot 的实际信任与纵向验收时如实记 BLOCKED，仍继续可独立工作的任务。

备选 A 为保持原横向模块顺序至全部完成后才打包，风险是集成反馈过晚；备选 B 为降低正式 Scope/免除 Gate 以抢发正式包，违反冻结基线与客观验收。所选方案仅改变实施优先级并增加受控中间产物，不更改架构、技术栈、`/api/v1` 或数据模型。

## 影响、风险、迁移/回滚与验证计划

- 影响：`AGENTS.md` 增加双里程碑/关键路径/自动验证纪律；`STATUS.md` 跟踪 Pilot 与正式 Gate 的不同状态。每个 WBS 仍只解决一项明确问题，变更先留痕再实施；稳定阶段可批量运行多个独立验证，不得以减测换速度。
- 风险：试用包被误认正式发行、未成熟 AI 建议被当业务事实、合成信任源进入发行物、聚焦纵向链导致其他已锁 Scope 被遗忘。控制：显式 Pilot 水印/版本说明和已知限制；人工确认保留；真实信任链失败关闭；正式 Scope 缺口维持追踪。
- 迁移/回滚：本 CR 不直接改数据库、API 或客户数据，无数据迁移。可恢复原 WBS 优先级；已形成的代码、测试、版本和 CR 历史不删除。后续功能变更各自使用相应 CR/Migration。
- 验证：先确认规则文档、状态和版本说明一致并同步；随后沿关键路径以目标/定向测试快速反馈，里程碑前执行完整回归、实际 Edge/PG、离线安装/重启/升级、权限/License/AI/插件/性能与可追溯 UAT。CI 可并行独立测试，但不得在仓库外泄露 Secret/客户资料。Windows Server 2025 与 Debian 13 仍是正式兼容目标；Debian 13 实机按用户既有指令暂跳过且不能据此标正式三平台 PASS。
