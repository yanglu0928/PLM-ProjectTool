# CR-PKG-011：当前应用候选隔离安装演练适配

- 日期：2026-10-25
- 发现 WBS：`PLT-PKG-01-A09-P51-A02` 编码前检查
- 状态：`CLOSED_VALIDATED`

## 差异与证据

`SOL-03-A06-P04-P03-A06-P02` 要求正式启动被缺失的产品公钥阻断后，继续当前源码 Windows 11 非发行候选的离线安装预检。现有 `tools/install_windows_caddy_go_atomic_rehearsal.py` 导入 `build_windows_unified_caddy_go_source_candidate.KIND`、`ARCHIVE_SHA256` 并固定旧 P33/P22 文件映射；其候选校验和目标映射均不接受 `WINDOWS11_CURRENT_APP_NON_RELEASE_CANDIDATE` 的 P47 派生包。直接复用会拒绝新候选；移除身份检查或改写旧工具则会弱化历史候选边界。

## 方案

- A：放宽/覆盖 P39 安装器的固定候选身份。拒绝：会改变已验证的 P33 专用合同，并可能造成来源与映射错配。
- B：新增独立的当前应用安装演练器，仅消费 P47 当前候选 manifest、`payload-sha256sums.txt` 和清洁暂存；明确 target mapping 与文件全集，复制至新私有临时 sibling、读回哈希后同卷 rename。已有目标、正式安装根、链接、候选身份/哈希不符均失败关闭；失败只清理本工具本次私有目录。选择 B。

## 范围、风险与回滚

- 只增加开发工具/测试/进度/版本记录，不改产品源码、API、ORM、Migration、权限、冻结基线或 P39 旧工具。
- 目标仅为 `Path.GetTempPath()` 直属 ASCII 一次性空根内的非发行文件布局；不注册 Windows SCM、不改防火墙/系统证书、不触碰 `C:\PLMTool`、真实数据库或客户数据。运行时/PG/Caddy若后续启动，仍需单独 WBS 与临时进程/端口/数据目录全清理。
- 不把临时测试信任源作为正式启动证据；正式公钥、Operator ceremony、目标服务账户/ACL、发行法律保持阻塞。
- 无数据迁移。回滚为弃用新演练器和隔离布局，P39/P47历史文件及正式安装保持不变；意外失败不能删除未知目录。

## 验证计划

先做单元正/负例：当前候选清单通过、错哈希/错误 kind/恶意路径/符号链接/多余文件/已存在目标/正式根均拒绝，注入复制中断时仅删除本次私有 staging 且目标不出现；再以从最新干净提交重建的候选在新ASCII临时根执行清洁提取、原子文件落地及独立读回/文件Hash核验，复核候选前后SHA、目录/端口/进程无泄漏。无任何正式信任或真实业务事实结论。
