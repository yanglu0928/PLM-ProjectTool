# CR-DOC-008：上传外部 I/O 与物理清理的同 ID 栅栏

日期：2026-09-26；状态：A01 OS 锁、A02 Content/Commit/Abort 全窗口接入、A03 内部精确清理/崩溃对账均在 Windows 11/隔离环境验证；A03-P03 前置核查确认 Server 2025 虚拟机可启动，但正式目标账户、旧版进程停写及应用恢复演练仍待，生产清理入口未开放，CR 未关闭。原 Gate 2 冻结提交 `64cdf09` 和既有 `0020`～`0026` 迁移均保留。

## 来源、冲突与证据

`docs/progress/doc-03-a04-a04-p04-p03-p02-cleanup-precheck.md` 已登记：Content/Commit 在短事务之间持有外部文件 I/O，Abort 可在其间把 FileObject 标为 `CLEANUP_PENDING`。若仅用数据库行锁、TTL 或 Hash 判定清理，先完成预检的操作可在清理后继续写同一上传路径。冻结 ADR-008 要求上传临时区、原子提升、补偿清理和维护模式，不授权在此窗口冒险删除。当前未有生产停写 Port。

## 方案比较与选择

- 不选仅按状态/Hash/TTL 清理：不能覆盖已经通过预检但尚未完成外部 I/O 的请求。
- 不选进程内锁：多进程/多实例不可见；进程崩溃后的锁语义不可作为交付依据。
- 不选跨外部 I/O 保持长数据库事务或行锁：违反 ADR-007 的短事务规则，且容易扩大事务持锁时间。
- 不选 PostgreSQL 会话级 advisory lock 跨越外部 I/O：虽然能保持业务事务短，但专用连接可能在请求仍写文件时断开并提前释放锁；单靠它不能作为物理删除证明。
- 选择在本地私有数据根下使用进程间 OS 文件锁，上传 UUID 映射至固定 256 个规范锁文件之一。Content、Commit、Abort 及清理都从首次状态预检前到最后数据库提交/文件操作完成持有同一锁文件句柄；进程终止由 OS 释放句柄与锁。非阻塞争用失败关闭，不让清理越过活跃写入。不同 ID 的哈希桶碰撞只造成额外串行，不会误共享正文。

## 差异、影响与实施序列

这属于既有本地文件系统/Document 安全边界内的恢复机制增量，不新增基础设施、Schema、公开 API 路径或第三方依赖。新增内部栅栏 Port 与本地 OS 锁适配；分步集成 Content/Commit/Abort，随后在受控清理命令中复用。官方 Windows 组合缺栅栏应拒绝发布写路由；升级时必须停止旧版写进程，确认无遗留活动操作后才能启用清理。此机制不自行提供维护模式或 Worker 收敛证明。

子任务：A01 锁适配及跨连接竞争/崩溃释放验证；A02 三命令窗口与 Windows 显式组合接入；A03 精确文件身份、引用及状态复核下的清理/崩溃对账。A01/A02 不等于 A03 已可删除。

## 验证、迁移与回滚

先在 Windows 11 临时私有数据根验证跨进程同 ID 争用、不同桶并行、进程崩溃释放、文件重解析/硬链接拒绝、错误隐藏；再结合隔离 PostgreSQL 18 覆盖 Content/Commit/Abort 预检与外部 I/O 并发、审计回滚、崩溃重试；最后检查 Scope、Intent、FileObject、零正式版本/保留引用、规范 Locator、同一物理对象身份/Hash/Size，以及硬链接/重解析点/仅最终文件/损坏/异常。Windows 11 先验，Server 2025 和正式账户留目标验收；Debian 13 按用户当前指令暂不验证。无数据库迁移；回滚应用代码需先停写并保持 `CLEANUP_PENDING`，绝不借回滚直接删除文件。

## 剩余风险

锁文件依赖单机本地文件系统与数据根权限；网络共享、多节点、旧版本无锁进程、管理员手工修改锁文件不在此证明内。正式清理必须另有停用旧进程与同 ID 栅栏完整覆盖的证据，不能单凭 A01/A02 宣称生产物理清理安全。256 桶会带来可接受的额外串行，需测试长上传争用和 Release 容量。共享存储、多节点及未升级旧进程出现时须另行评估。
