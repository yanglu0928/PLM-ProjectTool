# CR-SOL-006：GLOBAL Reference 脱敏人工确认记录与证明

日期：2026-10-08；状态：按 CR-EXEC-001 的持续授权，先登记后实施；Gate 2 原冻结提交 `64cdf09` 不改写。TraceLink：冻结 DM-05/API-04 → CR-SOL-004/005 → SOL-01-A04-P02-P03。

## 来源、冲突与选择

冻结方案要求 GLOBAL 参考材料有脱敏分类，且 GLOBAL ReferenceSolution 只能由 DeploymentAdmin 写。现有 0139 只有 `deidentification_class` 字符串，没有记录哪位管理员在何时、针对哪一组固定来源实施了人工核查；A04-P01 资格合同已经要求独立确认 ID、来源指纹、确认和失效时间。若把分类字段或 AI 建议直接当作确认，会伪造业务事实。

- 不选只用 `deidentification_class` 或 Audit 日志推断人工确认：缺固定来源集合、有效期和撤回状态。
- 不选改写既有标准能力 Review/权限：会扩大旧消费者边界。
- 选择新增 Solution 自有、GLOBAL 专用的追加式人工确认记录，固定 32 字节来源指纹、类别、适用性、实际操作管理员、确认/失效时刻和 Trace；撤回仅通过受控命令留痕。创建命令必须要求当前 Session/CSRF/License/管理员、明确人工确认动作与 Audit，不能由 AI 自动提交。Proof 必须重验当前授权、未失效/撤回和精确来源指纹。记录字段不是脱敏事实的自动生成器；没有真人操作的记录不得产生。

## 差异、迁移、回滚和验证

相对冻结 DM-05，增加一个实现人工确认不变量的辅助实体，不增第一版功能范围，不修改冻结 `/api/v1` 或产品授权机制。分解：P03-P01 先建立闭锁 Schema/ORM；P03-P02 实施受控人工确认写入与 Audit；P03-P03 实施受权 Proof 适配与完整来源资格回归。P01 不创建确认记录、不开放 API、不能声明人工确认可用。历史 Schema 0139 保留，新迁移 0140 只加空表；空表可降至 0139，非空拒降，无客户数据自动迁移。若需回滚，先停止新入口，保留已有记录并走正式数据迁移，不删除历史。验证须含空/已有数据升级、降级重升、ORM drift、约束/闭锁、回归；后续写/读另测撤权、过期、内容漂移、并发和审计回滚。
