# CR-PRJ-003：成员状态命令首次响应快照

日期：2026-09-25；状态：依据 CR-EXEC-001 持续授权批准执行；范围：PRJ-04-A12 幂等前置。

## 差异与证据

冻结 API-01 要求可重试 POST 的同 Key/同请求返回首次成功的原语义状态与结果；API-02 将成员暂停、恢复、移除登记为 `S,L,C,I,M,A`。现有 PRJ-02-A04 内部服务每次执行状态更新和 Audit，没有持久幂等；通用 `plt_idempotency_receipts` 仅存结果引用。成员可在首次状态命令后继续转换状态、变更角色/部门/显示名，因此从当前成员行重建首次 `MemberView` 不正确。`CR-API-001` 也禁止以可变当前视图冒充历史响应。

## 方案比较与选择

拒绝仅靠版本号/当前成员行（后续转换或移除后不可还原）；拒绝把完整响应正文放入跨模块通用收据（破坏最小化和 Project 归属）；选择新增 Project-owned、仅追加的 `prj_member_state_results`，每次成功状态命令保存类型化、不可变的首次 `MemberView` 字段及操作标识。通用收据只引用该快照；成员更新、审计、快照与收据完成在同一事务。操作范围区分 SUSPEND/RESUME/REMOVE，指纹绑定 ProjectId、MemberId 和强 If-Match 版本；异载荷同 Key 保持 409。重放重新校验当前 Session/CSRF、License 与 ProjectManager、目标归属，不重复转换/Audit；项目归档后仅允许重放既有成功，不允许发起新写。

此为冻结 DB Schema V1 后可追溯的实现增量，原 Gate 2 冻结提交不改写。`/api/v1` 路径、角色和状态机不变；既有状态事件不补造快照，只有新幂等入口产生记录。

## 影响、验证与回退

Migration `20260925_0017` 与 ORM 同步，只建新表和防改/防删触发器。空库及已有数据升级不修改原成员；验证空表 up/down、已有数据升级、三个操作的同 Key 并发与历史重放、异载荷冲突、审计失败回滚、授权/许可/归档拒绝、非空降级拒绝。降级仅在快照表为空时允许，避免丢失重放证据；已有记录须保留版本并走受控迁移。升级前备份数据库。正式发行信任源、Server 2025 和 Debian 13 不由本项宣称已通过。
