# CR-ENV-001 Windows Server 2025 虚拟机宿主 NAT 地址恢复

日期：2026-10-01；状态：`PROPOSED / NOT APPLIED`。本记录处理测试宿主网络环境偏差，不改变产品架构、Schema、API、安全机制或发行包。目标是在用户的 VMware Workstation Pro 中继续 Windows Server 2025 实机验收，而不是用 Windows 11 结果替代。

## 冲突与证据

目标 VMX 为 `D:\Virtual Machines\Windows Server 2025\Windows Server 2025.vmx`，网络类型 NAT。2026-10-01 从关机状态启动后 VMware Tools 为 `running`，来宾地址 `192.168.27.129`；宿主对该地址的 TCP 3389、5985、5986、445 均未连通。检查后正常关机，`vmrun list` 再次显示运行 VM 数 0。没有在来宾内安装、修改配置或读取客户数据。

宿主 `VMware Network Adapter VMnet8` 状态 Up，但 IPv4 为链路本地 `169.254.190.187/16`、DHCP Disabled；VMware DHCP/NAT 配置均指明此网络为 `192.168.27.0/24`，宿主地址应为 `192.168.27.1`，NAT 网关为 `.2`。VMware DHCP/NAT 服务正在运行。当前终端令牌非管理员，不能安全执行宿主网卡修复。**推断**：宿主 VMnet8 地址漂移足以解释宿主无法直连该 NAT 来宾；修复后仍须重新确认来宾防火墙/监听状态，不能由现有端口失败单独断定来宾服务未启用。

## 方案与实施边界

- 方案 A（建议）：由具备宿主管理员权限的受控操作恢复 VMnet8 的 `192.168.27.1/24`，先核对该地址未被占用并保留当前网卡配置快照；恢复后重新启动指定 VM，复测地址、路由与所需管理通道，再做来宾内的目标账户/安装前置检查。此变更可能影响同一 NAT 网络的其他 VM，须在维护窗口确认。
- 方案 B：另建专用 host-only/桥接管理通道并在来宾配置；改动更多，需核对企业网络策略与来宾防火墙，不作为当前首选。
- 不采用把 Windows 11 通过结果推定为 Server 2025 兼容，也不通过修改测试结论绕过发行门禁。

实施前提：具备宿主管理员权限、明确维护窗口与其他 VM 影响范围；当前终端未满足，故本 CR 仅登记，**没有执行任何宿主网卡修改**。未来实施需记录变更前后 VMnet8 地址、路由、其他 VM 连通及目标 VM 验收；若失败，恢复原网卡配置并正常关机目标 VM。此前 Server 2025 安装、目标账户 ACL、服务恢复、正式 License/HTTPS 仍为未验证；`release_eligible=false`。
