# PLT-PKG-01-A09-P51-A50：待办到原文位置的最小跳转审计（编码前检查）

- 日期：2026-11-02
- 状态：编码前检查完成；编码前须先完成下列参考资料核对。

## 目标

落实用户已有偏好：AI生成的调研/交接待办应能直接定位到源文件和具体位置，让人查看原文再确认；不把大段原文复制进表格要求人工填表。本WBS只审计并实现最小可用的源位置跳转，不改业务事实来源和客户数据流程。

## 编码前检查要求

1. 按仓库流程恢复AGENTS、STATUS、V1.1执行规则和项目Skill；读取当前调研/交接待办前端、API Contract、TraceLink/Document位置数据模型和相关 ADR。
2. 只读确认当前源引用是否含有可信文件ID/版本/页码或段落/页内坐标，以及用户附件/文档预览路由如何做权限验证。
3. 优先复用已有TraceLink或文档定位契约，跳转目标必须绑定不可变源文件版本；禁止拼接任意文件路径、读取本地绝对路径或绕过ProjectId访问控制。
4. 若当前模型没有安全来源锚点，先记录差异、风险、迁移/兼容与验证方案，并按持续授权选择只读、安全、向后兼容的实现；任何冻结API/DB Breaking Change先建立CR，不能静默扩schema。
5. 仅在已有源链接允许时提供“打开原文位置”操作；定位失败时退回文档查看入口并说明页码/段落，不丢失当前待办编辑状态。
6. 验收需验证同项目权限可访问、跨项目/无权限/失效版本拒绝、页码/段落正确、缩放/重载安全；使用合成文档，不外发客户数据。云端/沙箱优先，禁止用户本机运行；不得推定Win11兼容。

## 单一范围与排除项

只解决“待办定位到原文”的交互链。不得顺手改文档解析、AI质量、提示词、业务表单、客户数据上传或其它列表。用户对持续执行已授权，无需等待普通确认；客观缺少定位能力时转向不依赖该能力的安全工作，并记录阻塞。

## 回滚

移除入口/跳转组件即可回滚；不改待办业务事实，不应改动历史正式确认结果。若需改DB/API，新增CR说明兼容迁移后再实施。
