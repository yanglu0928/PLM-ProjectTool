# PLT-PKG-01-A09-P40：Windows 新装待发布目录中断恢复

日期：2026-10-01；状态：`NON_RELEASE_INTERRUPTED_COPY_RECOVERY_PASS / FORMAL_INSTALL_BLOCKED`。依赖 P39 新装文件落地及 P38 正式安装前置阻断；不改 Gate 2 冻结基线。

编码前检查：Phase 2、Gate 3 开放；本项只处理 P39 进程中断遗留的私有临时目录，不处理正式根、已有安装升级、业务实体/API/权限/Migration。验收：待发布目录旁有无敏感信息的固定候选归属标记；只读发现区分未归属、有效未完成、标记损坏、目标已存在及发布后标记滞留；仅有效未完成且目标不存在时可逆地同卷隔离，绝不自动删除或发布残件。风险是伪造标记、目录被并发修改、进程崩溃在标记写入前、强杀和断电耐久性。

P39 复制器现在先写同卷 sibling `*.intent.json`，含版本、待发布目录名、全新临时目标及 P33 固定 SHA；标记 `fsync` 后才复制，正常发布后删除标记。标记不在安装布局中、不含密钥或客户数据。捕获异常仍只清理本次私有目录和标记；若进程突然终止，则 `tools/recover_windows_caddy_go_atomic_rehearsal.py` 可 `--discover`/`--inspect`。对确认归属且目标不存在的残件，`--quarantine <确切临时目录>` 只将目录与标记重命名至同卷 `plm-p39-quarantine-*`，保留全部字节供检查，不删除用户文件；标记不一致、无标记、链接、目标已存在或范围不安全时拒绝。两次 rename 不是一个原子操作：第二次失败时目录与原标记均保留，需人工对账，不能报恢复完成。

Windows 11 定向单元：P40 六项（含独立子进程 `os._exit(93)` 留下半文件与标记、只读发现、隔离后文件仍可读、无标记/损坏标记/已有目标/发布后滞留拒绝误移动）全部通过；P39 原四项回归通过。修订后的 P39 用真实固定 P33 ZIP 再落地 21,115 件至新的 ASCII Temp 目标，`recovery_marker_retained=false`，独立布局验证器核全部文件集/Hash 和映射 SHA-256 `d4072ed23558da5026911fad3575ee8b4d67944814b58096b6587c1bf9908580` 通过；`--discover` 在单元清理后返回空列表。正式 `C:\PLMTool`、SCM、证书、已有数据库未触碰。

限制：验证的是进程突然退出及可逆隔离，**不是断电/文件系统耐久性证明**；标记可由本机同权限进程伪造，不能视为安全认证，且进程在 `mkdtemp` 后、写标记前崩溃的目录只能报告未归属，不能自动隔离。正式目标账户/ACL、信任源、第三方发行合规、Server 2025 与 Debian13 实机及安装/升级 Gate 仍未验；`release_eligible=false`。兼容性：仅 Windows 11 临时目录文件流程，业务 API/Schema 不变。升级说明：无迁移，不适用于已有安装升级。回滚：保留 P39 原提交；不用恢复工具即可停止新流程，已隔离目录保持可读，不自动删。
