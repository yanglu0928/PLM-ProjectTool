# DOC-03-A03-P04-P02 双路径硬链接中断窗口恢复

日期：2026-09-25。版本：`0.1.0.dev0`。状态：内部恢复子任务 PASS；P04 整体仍待异常隔离分类。

当前 Storage Adapter 的无覆盖提升在最终目录建立硬链接后才删除暂存入口，因此崩溃可留下两条路径。新增明确指定 FileObject 的内部恢复操作：要求两侧都是同一普通文件的恰好两条硬链接，依数据库记录的 SHA-256/Size 做有界流式双侧校验，然后只删除暂存目录项，重校验独占最终文件，最后以独立幂等作用域在数据库行锁事务中写 AVAILABLE、状态事件、Audit 与收据。若数据库/审计提交失败，最终文件已独占但数据库仍 STAGED，可再由 P04-P01 恢复。

不同文件、额外硬链接、内容不符、越界或缺失都失败关闭，保持 STAGED 且不删任一文件。本操作不做全盘扫描或自动隔离/清理。Windows 11/Python 3.13 后端 459 项无失败（2 项符号链接场景因账户权限跳过）；合成双路径、不同文件、回滚与二次恢复在 PostgreSQL 18 临时库 PASS；P03 发布回归及开发 wheel PASS。

无新 Migration、公开 API 或依赖；升级仍须已有 `20260925_0022`。正式权限/上传类型验证、异常隔离分类、Server 2025/Debian 13 和最终程序包未完成。追溯：`DEC-20260925-095`、ADR-008、冻结 DM-03、`validation/doc-03-a03-p04-p01-file-recovery/verify.py`。
