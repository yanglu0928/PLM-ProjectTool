# JOB-02-A06-P03：项目 Job 详情人工取消入口

2026-10-02 / Phase 2。编码前核查：JOB-02-A06-P01/P02、冻结 Job 取消项目路径、Windows 显式写组合满足。本项仅修改项目 Job 详情页面和页面测试；Job 与 ProjectId/强 ETag 是输入，服务端仍负责真实 creator/PM、License、Owner 与原来源授权。无实体、Schema、后端 API、角色/依赖变动。验收包括显式确认、写前操作号保存、结果未知保持、撤权/路由代次隔离、前端回归。

实现：只针对当前 PROJECT Job 活跃/取消请求状态显示“申请取消”；用户填写原因并核对任务号、状态、版本。发送前在按用户隔离的 browser sessionStorage 保存原 Job/Project/ETag/Key，保存失败零 POST。成功仅显示首次回执并要求重新 GET；未知结果保留原操作号，跨页可回原任务核对，禁止自动重试/生成新操作号。只有新 GET 发现版本变化、用户显式声明核对当前任务和适用审计，才允许清除本地待核对记录；版本未变化不能据此判定原操作失败。服务端仍可拒绝非原创建者/项目经理。异常、401、撤权及跨路由旧响应不泄露私有内容。

验证：页面定向 10 项、前端全量 1161/1161、typecheck/build PASS。测试中发现 `ref` 深代理使刚保存对象与清除参数引用不等，改为 `shallowRef` 并重测；Unicode 控制字符写前拒绝、sessionStorage 故障零请求已覆盖。无 Migration。已知问题：真实浏览器、正式信任、Server2025/Debian、原操作号服务端精确回查、全Owner/性能/Gate3未验；当前本地非发行ZIP须后续重建。下一项执行显式 Windows 隔离 ASGI/PG 的前后端真实网络验证，并继续独立业务任务。
